The original proposal, current direction, major UI systems, and technology used for the COMP 585 UI Game.

Original Proposal

The project was proposed on September 2, 2026 as RPG + Adventure Game (Name Pending). The central goal was to build a small open-world game that demonstrates course knowledge through practical UI and GUI implementation while still producing an enjoyable game.

The intended audience is RPG and adventure-game players. Major inspirations include large open-world RPGs such as Fallout, Skyrim, and Oblivion.

UI / UX Goals

The project investigates how game interfaces can be created, implemented, and improved so they remain useful and intuitive for players ranging from beginners to experienced users.

Early planned interfaces included a character sheet, dialogue UI, open-world map, game launcher, and other interaction-focused screens. The project also explores HUD elements, contextual prompts, inventory interaction, menus, and visual feedback.

Current Implementation

The current build is an FPS / survival-style Unity prototype. The player can move through a 3D environment, use a rifle, interact with world items, manage an inventory, and receive feedback through screen-space and world-space UI.

The original proposal listed Godot and C++ as the planned engine and programming language. During development, the implementation moved to Unity and C#, with Unity UI and TextMeshPro used for interface work.

Inventory, Hotbar, and Tooltip

The inventory uses a grid layout to organize item slots and allow the player to move items between locations. An eight-slot hotbar exposes commonly used inventory slots directly on the HUD.

Hovering over an item displays a temporary tooltip containing item information such as its name, type, description, and quantity. The tooltip uses an overlay pattern because the information is only needed while inspecting an item.

Combat and Status HUD

The combat HUD includes an ammo counter with reload tracking and a no-ammo alert when the player attempts to fire without usable ammunition.

Player health and stamina are displayed as persistent HUD elements. Enemies use a world-space health bar positioned above the target so health information remains visually associated with the object.

Menus and Interaction Feedback

A radial menu presents multiple choices around a central point while allowing the game world to remain visible. A separate menu hint provides contextual input guidance on the HUD.

Floating interaction text uses world-space UI near interactable objects so players can identify items and understand available actions without opening a separate screen.

Additional UI Ideas

Planned and exploratory interface ideas include a real-time date display, date picker, UI and crosshair color selection, difficulty controls, camera-sensitivity and FOV sliders, graphics settings, custom cursors, a minimap/full map, crafting, dialogue, character sheets, and computer/puzzle interfaces.

Data and Web Direction

The current game is designed around locally stored application and user data. Game assets are distributed with the application.

The original proposal also identified Firebase as a possible future service for a web-based version or online data features. That remains a future direction rather than a currently completed system.

Layout Patterns

The inventory uses a Grid pattern, while the hotbar uses a compact horizontal grid / stack. Temporary tooltip information and most gameplay status indicators use Overlay patterns. Enemy health and interaction labels use world-space overlays, and the menu wheel uses a radial / circular layout.

Future UI screens will continue to incorporate layout and interaction patterns covered in COMP 585 where they improve readability or usability.

Development Process

Development is organized around roughly two-week milestones. Planned milestones include world creation, player controls, interactable objects, informational UI, major gameplay menus, and final integration and polish.

Technology Stack

Current development uses Unity, C#, Unity UI, TextMeshPro, Visual Studio Code, GitHub, and public / Unity Asset Store assets.

The proposal originally specified Godot and C++; those technologies describe the initial plan rather than the current implementation.
